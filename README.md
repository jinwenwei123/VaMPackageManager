# VaM 包管家

简洁的中英双语本地资源管理工具，当前源码版本 **1.0.0**。本仓库仅包含源码，不包含用户数据、密钥、运行时或编译后的 EXE。准备运行环境并编译后的便携发行包可双击 **`VaMPackageManager.exe`**，在浏览器打开 WebUI，无需另行安装 Python 或 Node。

本次源码发行从 **1.0.0** 开始编号，已包含此前全部功能更新。下文暂保留的其他版本编号属于内部开发历史，不代表本次源码发行的版本顺序。

在 **AI 与设置 → 语言 / Language** 切换简体中文或 English。语言保存在管家 `data/language.json`，跨游戏目录共用，重启或更换本地端口后保留；切换会刷新已打开的管家页面，请先保存编辑内容。界面和后续 AI 简介、标签、预设草稿及助手回复使用所选语言；已在进行的生成任务沿用该任务的语言。已有简介、标签、聊天记录、包名、文件及文件夹名称均保持原样。分类的英文仅用于显示，内部分类值和实际目录不翻译、不改名；切换语言不会触发扫描、生成、移动或重写已有内容。

未修改的内置对话预设（标题及提示词）随界面语言切换，手动新增或改写的预设保留原文；打开预设直接保存、调整常用栏不会取消其语言切换能力。默认启动方案“基础收藏”在英文界面显示为“Base favorites”，方案标识、收藏联动及存储名称不变；自行改名或创建的方案保留原名。

首次启动默认管理工具所在目录的上一级 `AddonPackages/`，以后记住上次选择的游戏目录。请保留整个 `VaMPackageManager` 文件夹；只复制 EXE 无法运行。

新增默认主页，导航入口位于收藏夹上方。默认十张卡片汇总游戏目录、资源、收藏、启动方案、AI 服务、简介与标签进度、资源检查、API 用量与缓存、外观和最近操作；右上角“›”进入对应页面。点击资源数量／分类直接筛选，点击收藏打开详情编辑，点击模型定位设置，外观可直接调整。主页只读取已有数据，不自动扫描或生成；后台更新保留搜索输入。

主页右上角“自定义主页”可勾选增删卡片，通过拖动手柄或上下按钮排序，保存后生效，也可恢复默认。共16种卡片，额外提供最近更新资源、完整分类、固定基础包、对话助手、资源位置与占用、索引状态；允许隐藏所有卡片，仍可重新添加。每个游戏目录分别保存布局，主页只加载已显示卡片所需的数据。

**AI 与设置 → 游戏目录**支持保存多个包含 `AddonPackages` 的游戏根目录、改显示名称及一键切换；主页“游戏目录”卡片也能直接切换。切换刷新所有管家页面，并切换索引、简介、标签、收藏、启动方案、固定包、操作恢复记录、生成队列、对话、预设、API用量、AI设置与主页布局。新目录首次沿用当前 AI 连接配置和配色，此后独立保存。切换不自动扫描、生成或搬动资源；新目录需自行更新索引。

原游戏索引、简介等元数据继续使用 `data/`，不搬迁或清空；新目录使用 `data/workspaces/<目录ID>/`，登记在 `data/game-directories.json`。即使两个目录中有同名包，也分别保存简介和标签。原停用库沿用既有位置，新目录默认使用自身 `.DisabledPackages/`，名称可自定义。路径失联时保留数据，可切换其他目录；不会自动重建失联游戏路径。重复路径及相互重叠的包库不能登记或切换。备份全部管理数据时保留完整 `data/`，游戏资源仍在各自游戏目录。

添加游戏目录时，点击游戏根目录右侧的“选择文件夹”，即可打开 Windows 原生文件夹窗口，选择包含 `AddonPackages` 的游戏根目录；重新绑定位置也支持此按钮，仍可手动粘贴路径。取消选择保留表单内容。添加时目录名称自动取根文件夹名；手动修改过的名称不会被后续路径选择覆盖。若名称与已保存目录重复（忽略前后空格及大小写），会显示提示并禁用保存，改成不同名称后才能提交。后端同时校验重名，改名及恢复绑定也不能绕过；保留数据恢复时可在绑定窗口修改名称。已有历史重名记录不被自动改写。

启用文件夹 `AddonPackages` 以灰色禁用字段显示，不能聚焦、选取或修改；停用文件夹仍可自定义。目录选择窗口打开时不阻塞状态轮询或切换，切换目录后旧窗口返回的结果不会写入新目录。选择本身不添加目录、不扫描或移动文件。

**资源文件夹**在“AI 与设置 → 游戏目录”配置。启用库始终为游戏根目录下的 `AddonPackages`，不可修改；停用库默认为 `.DisabledPackages`，添加目录时可填写自定义文件夹名（仅一级相对名称）。当前目录也可修改停用名称：保存会整体移动原停用文件夹，保留 VAR、附件、简介、标签、方案和既有操作恢复记录；目标已存在则拒绝，绝不合并或覆盖。旧版 `data/disabled` 默认保留原位，只有显式保存资源文件夹才迁移。文件夹尚未创建时只保存配置，首次存入资源时创建。任务、上传或 VaM 运行期间禁止改名；路径变更失败会回退，中断后重启恢复。所有页面在修改后刷新，旧页面操作失效。

自定义名称按游戏目录保存在各自 `catalog.sqlite3` 的 `settings.disabled_folder`，启用位置不提供可改配置；新目录首次打开前的名称登记在 `data/game-directories.json`。切换目录读取该目录自己的设置，不沿用其他游戏的绝对路径。

**移除与恢复目录**：每条目录右侧的“移除”只解除列表绑定，保留游戏文件、索引、简介、标签、收藏、方案、聊天、设置和隔离区。当前目录（包括最后一个）也可移除，随后进入“未选择游戏目录”，不再操作原目录；重启保持此状态。下方“已移除目录的数据”显示保留记录及数据位置。重新添加原路径会恢复原数据 ID 和原停用文件夹设置；同一路径有多份保留数据时，请从列表明确选择一份恢复。

**游戏搬家**：先关闭游戏和管家，移动完整游戏目录（包括自定义停用库和 `.PackageManagerStorage`），再打开管家，通过原条目的“更改位置”或保留记录的“恢复／重新绑定”填写新的游戏根目录。只更新绑定，不扫描、搬包或清空数据；简介、标签、方案和操作恢复记录仍沿用。管家留在原处时数据留在原工具的 data；管家随游戏一起移动时沿用移动后的 data。索引存在停用资源而新目录缺少对应停用文件夹时会拒绝绑定，避免遗漏资源。目标路径若已被另一条记录使用，先移除那条绑定，再绑定所需的数据，两份数据均保留，不合并或覆盖。新位置仍要求包含固定的 AddonPackages。

修改当前绑定会刷新所有管家页面；后台任务或上传期间禁止移除、重新绑定。数据登记仍保存在 `data/game-directories.json`，保留数据的 ID 不变；“未选择”页面使用独立的 `data/unselected/`，不会清空原目录数据。

切换前先保存表单；生成、对话、上传或文件任务进行中时须等待完成或先暂停／停止，未完成的文件恢复操作也需先处理。切换后旧页面请求会被拒绝并自动刷新，防止跨目录误写。关闭全部管家页面，待后台退出后重新打开原EXE，以加载本次后端改动。

**生成完成提示**：简介或标签任务完成后，点击右上角×关闭，状态按游戏目录和本轮任务保存到管家数据。重新启动、换本地端口、换浏览器或切换游戏目录后，该轮完成提示不再出现。正在生成、暂停或失败的任务继续显示进度与恢复入口；新一轮任务正常显示，不受上一轮关闭操作影响。

**一键归档**：收藏夹和资源库页面顶部均提供“一键归档”。收藏夹处理全部收藏，资源库处理全部资源，包含其他页和停用包，不受搜索、分类或状态筛选影响；无需勾选，保留已有选择。点击后先展示范围、包数和原有文件移动预览，确认后执行，可从操作记录恢复。继续沿用原归档规则，包括按当前启动方案校正全库启停。仅整理部分包时仍可勾选后使用“按分类归档”。

**重复清理 → 隔离区**现在可以在应用内管理暂存副本。页面顶部“查看隔离区”可直接跳转，面板显示当前游戏目录的隔离路径、文件数、大小及批次；“查看文件”列出隔离路径、原位置和大小，按80个文件分页。可恢复整批，或勾选批次后“清理选中批次”，也可“清空隔离区”。未关联操作记录的普通文件单独列出，符号链接、目录联接及特殊文件跳过并提示。

永久清理先显示文件数、合计大小和清单，勾选确认后才能执行；**不经过回收站、无法撤销**。仅删除预览快照中的隔离文件，预览后新增的文件保留；删除前再次核对路径和文件状态。启用库、停用库、简介、标签和收藏不受清理影响。操作记录保留，已开始删除的批次标记为无法整批恢复；取消或失败后保留剩余文件，可以重新预览继续清理，尚未开始处理的其他批次仍可恢复。存在未完成的文件移动时，须先恢复该操作再清理隔离区。

隔离区跟随当前游戏目录切换。此次为后端与页面更新：关闭全部管家网页，等待后台退出，再打开原EXE生效。

对话输入框支持拖动整个上边缘调整高度：向上拖增高，向下拖缩短，浏览器记住所选高度；窄窗口会自动限制高度，保留聊天区和发送按钮。聚焦边缘后也可用上下方向键调整，Home恢复默认高度。


**1.20 游戏目录内的暂存与隔离区**：导入暂存、下载暂存和隔离区改为各游戏根目录下的 `.PackageManagerStorage/<数据归属ID>/imports`、`downloads`、`quarantine`。停用库默认 `.DisabledPackages`，启用库仍固定为 `AddonPackages`。归属ID用于隔离不同管家数据目录，防止把另一份索引的隔离文件混在一起。索引、简介、标签、设置、方案、聊天和操作恢复记录继续保存在管家的 `data/` 或 `data/workspaces/<目录ID>/`。

旧版 data 下已有的暂存和隔离文件继续在原位使用；在“AI 与设置 → 游戏目录 → 游戏管理文件”点击“迁移旧管理文件”，后台带进度迁移，中断后点击“继续迁移”。未完成迁移时暂停资源写入，避免两边同时变化。迁移不合并或覆盖同名目标，旧隔离批次仍可用原操作记录恢复。游戏搬家或备份时必须一并保留 `.PackageManagerStorage` 和管家的 data；移除目录登记不会删除任何管理文件。

同盘仍直接重命名；跨盘改为复制到目标盘的独立临时位置、SHA-256 校验、无覆盖地放入目标位置，再删除源文件。取消、复制失败或目标冲突不会覆盖已有内容；已放入目标但尚未清理源文件的转移保留记录，文件操作恢复和管理文件迁移可继续处理。导入或下载异常时的残留暂存会保留，启动时不再按24小时自动删除。

升级后关闭全部管家网页，待后台退出再打开原EXE，确认当前版本号。已迁移管理文件后请勿直接换回不认识新位置的旧版程序；要降级，应先关闭管家并将各类文件及停用库恢复到原位置，保留 metadata 和恢复记录。

## 1.19 参考 DeepSeek Harness 的上下文管理

参考官方 `deepseek-ai/deepseek-harness` 固定提交 `687f282e`，API 对话改为计量完整请求（system、工具 schema、消息、图片估算和输出预留），优先模型目录容量，官方已知 DeepSeek 型号回退1,048,576 tokens，未知兼容接口保守用65,536；可在设置页展开“上下文容量设置”手动覆盖。估算区分中文与ASCII，并以同模型/接口最近实际 `prompt_tokens` 校准；未改变的消息复用计量结果，聊天页显示近似输入 tokens。

达到压力阈值后先裁剪**旧的**大工具结果，保留近期完整调用/结果；仍过大时才发起一次同对话模型的语义摘要请求，复用原 system、tools 和历史前缀，最后追加摘要指令。摘要不执行工具；非空、完整且充分缩小后才替换旧前缀，近期原文、推荐 key/顺序和操作回执继续保留。摘要会消耗额外API用量，单独列入“上下文摘要”；不会每轮运行。只有明确的服务端上下文超限、且已有持久缩减时才重试一次模型请求，绝不重做已完成工具操作。

模型历史单独保存于 `data/agent/api-context.json`，界面进度更新不再反复序列化整份模型历史；压缩前原文保存在 `data/agent/context-checkpoints/`。旧格式自动迁移，停止/新对话/重启继续有效，封面Base64仍不写入持久记录。备份对话应保留整个 `data/agent/`。

简介、标签和联合生成按数量与输入预算拆批；单包资料不拿语义摘要代替，不向下一批追加上一批内容。缓存统计分别列出仅简介、仅标签、简介＋标签、对话、上下文摘要与预设草稿。服务端缓存不能保证固定比例；不同包资料/图片天然需要新计算。

关闭全部管家网页，后台退出后重新打开原EXE，确认当前版本号。本次验证未调用付费模型，性能数据不等于实际缓存命中率。

## 1.18 对话上下文与 API 缓存

助手不再因为搜索/详情结果膨胀而整轮删除用户对话：优先精简工具结果，保留用户发言、回复及按顺序展示的推荐卡片。升级后首次 API 续聊会从现有可见记录恢复上下文；更换服务或模型也会带入近期对话和推荐 key。网络失败、停止或达到工具循环上限时保存已取得的上下文；新对话仍清空当前上下文。历史状态与操作结果需要重新核对，极长会话会保留有省略标记的摘录，并非无限记忆。封面 Base64 仍只保留在当前轮内存。

生成请求使用固定的提示词与 JSON schema 前缀，包资料使用排序、紧凑 JSON，图片放在文字之后；聊天通常只追加消息，超过容量时才压缩历史工具数据，以便复用相同前缀。不改变现有简介/标签提示词原文，不自动重新生成已有内容。

**AI 与设置 → API 用量与缓存**显示更新后累计请求、输入/输出 tokens、按 tokens 加权的缓存命中率及最近请求命中率。对话与生成分开计数，不同接口/模型分别记录；不报告缓存数据的请求不计入命中率分母。统计仅保存数值、模型和接口域名于 `data/ai-usage.json`，不保存密钥或请求正文。DeepSeek 缓存由服务端自动管理；不同包的资料与图片不同，仍需新计算，不能保证固定命中比例。说明见 [DeepSeek 官方缓存规则](https://api-docs.deepseek.com/guides/kv_cache/)。

关闭所有管家网页，等待后台退出后重新打开原 EXE，确认当前版本号 即可生效；不必点击“新对话”。

## 1.17 内容标签与多模态推荐

“一键 AI 简介”新增 **简介＋标签 / 仅简介 / 仅标签**，支持全部重生成或仅补充未生成。默认联合生成、全部重生成，点击确认才开始；要保留旧简介并首次补标签，选择 **仅标签 → 仅补充未生成**。联合补充也分别跳过已完成的简介与标签，不多生成再覆盖。旧队列继续只生成简介。

生成完成后的进度提示可点击右上角“×”关闭；本浏览器刷新后保持关闭，下一轮生成正常显示，不影响已保存的简介与标签。

大图及助手推荐卡片的分类标签放在标题下方，不覆盖封面；最多展示3个，其余用“+X”表示，详情显示全部。内容标签在资源列表、大图和推荐卡片的简介上方显示前3个，其余以“+X”计数提示，不提供展开按钮；无内容标签时显示“暂无标签”占位，进入详情直接显示全部标签，可用逗号分隔手动编辑。搜索同时匹配分类、标签、简介、包名和路径。每包通常4–12个标签，最多24个；使用预设词表，有证据时可自定义。内容提示不是官方年龄评级，年龄风格只作外观描述，不据外貌推断实际年龄。

简介和标签独立存储在本地索引，分别记录完成状态、包指纹与批次。升级不修改已有简介；移动、收藏不丢标签，包内容变化会使标签标记为待更新。文件名修复及 JSON 修复同步保留标签和恢复记录。旧版命名恢复日志若缺少后来新增的标签，会阻止恢复并提示，避免标签丢失。标签不写入 VAR、不创建包副本，也不影响启用方案。

助手先按分类、标签和简介检索，再通过 `inspect_package` 核对元数据、内容清单和场景线索；`view_package_cover` 只给支持识图的**对话模型**发送真实封面，每轮最多4张。Codex 使用原生图片工具返回，兼容 API 使用图片消息；API 图片仅保留在当前轮内存，不把 Base64 写入聊天历史。非识图模型保留文字检索；封面中的展示配件不等于包内包含。

实际提示词和标签预设位于 `src/vampm/summary_content.py`、`src/vampm/content_tags.py`；对话提示词位于 `src/vampm/agent.py`。使用现有简介模型设置和识图开关；助手看图能力按对话模型判断。

## 包异常修复与定位文件（1.16）

入口：**依赖检查 → 包异常修复 → 分析与修复**。自动使用设置中的**简介生成服务和模型**。先生成建议，按“文件名格式”“meta.json 语法”“其他问题 / 暂不支持”分组；可打开上次建议、查看差异、编辑建议文件名、逐项勾选后点“执行所选修复”。分析本身不修改 VAR，也不按方案移动文件。

- **文件名格式**：保留原有修复能力，例如 `Sample.Asset.2_2.var → Sample.Asset.2.var`。保持原启停位置，迁移收藏、简介、固定名单、方案和资源组身份；同名目标分目录保留。版本或作者缺少依据时会标记推测，需核对。
- **JSON 语法**：处理 `meta.json` 的缺括号、尾逗号、漏逗号、引号或反斜杠转义问题，也包括“已兼容读取”的黄色提示。AI 返回局部替换，程序检查严格 JSON、字段/文本保留；原本可兼容解析时还比较解析结果。大量 Windows 路径的转义候选会先与 ZIP 内真实文件名核对，再交给 AI 审核。不能可靠验证的建议不可勾选。
- **其他问题**：坏 ZIP、缺少元数据、重复内部路径、加密 ZIP、过大的元数据及纯发布信息不符会列出原因。没有原始信息时不编造 JSON；不会通过修改作者、依赖或授权字段来消除提示。当前覆盖索引读取的 `meta.json`，不批量改写场景、预设或插件 JSON。

JSON 修复只重建元数据条目，其他资源的原始压缩数据逐块复制并核对，不解压重压贴图、模型等大文件。每次需要约一个当前待处理包大小的临时空间；长期恢复记录仅保存原元数据记录、ZIP 目录和操作日志，不另外保留整份 VAR。关闭 VaM 后执行；保持包名、路径、收藏与简介，更新依赖索引及内容哈希。发布页大小不符等独立警告仍保留。修复语法不等于补齐依赖或保证场景完全正常。

文件名建议分批保存，JSON 建议逐包保存；网络失败后可以继续。模型回复不完整或修改无法验证时会列为暂不采用，其余候选继续处理。API 请求的 JSON 修复输出预算增至 12,288 tokens，Codex 沿用 CLI 输出限制；不改变简介/聊天的预算与思考配置。若同包同时有命名和 JSON 问题，先修 JSON，再重新分析命名。

修复会分别生成“修复包文件名”和“修复包内 JSON”操作记录，可按倒序恢复。JSON 恢复会验证整包原始 SHA-256；后续移动或内容改动需先恢复，防止覆盖。中断后保留恢复记录和必要临时文件，先恢复中断操作再继续。不要手动删除尚需恢复的操作记录。

**打开位置**现在使用 Windows Shell 直接打开父目录并选中具体 VAR。详情“资源位置”里的每份副本还有独立的“定位文件”按钮；包已移走时提示更新索引，不会悄悄跳到工具目录。此修改通过原 EXE 加载，无需重新打包：关闭所有管家网页，等待后台退出后重新双击 EXE，确认当前版本号。

## 扫描、归档与当前方案（1.14）

- **没有应用方案**：只启用固定基础包及其可用依赖。保存方案、选择预览都不算应用。手动放入 `AddonPackages` 的普通新包，在点击“更新索引”或“深度扫描”后移入 `.未启用模组/主分类/`；收藏包进入 `.未启用模组/收藏/主分类/`。
- **已应用方案**：扫描、导入及补依赖完成后，自动按该方案的主包和递归依赖校正启停；其他包停用。已应用基础收藏时，新收藏进入 `AddonPackages/收藏/主分类/`，外部依赖进入普通启用分类；取消收藏后仍被方案需要的包继续启用。缺失依赖仅提示。
- **明确恢复全部启用**：这是单独的启用模式，后续扫描保持全部启用；要回到仅基础包，执行“停用普通包并整理”。
- **归档**：所选包整理到对应主分类，同时校正全库的启停状态。三个逻辑区域分别是普通停用、收藏、普通启用；收藏随启停在两个库的同名 `收藏/主分类/` 目录间移动，文件只有一份。固定基础包继续常驻 `AddonPackages/基础包`。
- **保留目录与名单**：已识别的整组目录、图片和说明跟随主包，独立 VAR 才直接放进分类。同名副本分子文件夹保存。文件夹方案保留已经纳入的包身份，归档后不会因原目录搬走而失去成员，并继续从来源目录发现新增包。
- **操作与恢复**：先退出 VaM；扫描会实际移动文件，归档仍先预览再确认。记录保存在“操作记录”，可以从新到旧恢复。普通索引刷新只重新检查变动包；没有文件移动时不增加空操作记录。仅修改主分类/简介不会立即移动，需归档；扫描发生启停转移时会使用当前主分类。

## 交叉分类、固定基础包与默认收藏方案（1.11）

- **一份文件，多个类别**：按包内实际场景、外观/服装/发型等预设和资源建立内容标签。例如同一包可同时出现在“场景、人物、服饰”；分类数量可相加超过“全部”，不会为分类创建副本。主分类用于磁盘归档，可以在详情编辑。
- **整组资源目录**：原本带图片、说明或附带 VAR 的资源按整个文件夹存放，例如 `收藏/人物/Sample.Character.1/`，内部文件及子目录一起保留。按主包分类、收藏或取消收藏时整组转移；启用主包会包含组内可用包和递归依赖。已固定的必要插件优先留在基础目录。独立 VAR 才直接放在 `主分类/包.var` 或 `收藏/主分类/包.var`。
- **分类目录**：启用库是 `AddonPackages`，停用库默认是 `.未启用模组`（可在设置中改名）；统一使用“人物”，不再使用“人物卡”或“包管家分类”前缀。已有同名文件在包名目录下使用 `副本-编号/` 隔开，原名和内容保持不变。多个分类只是索引视图，不产生实体副本。
- **固定基础包**：初次保留整合包原“基础包”目录；固定包及可用递归依赖常驻 `AddonPackages/基础包`。原已在该目录中的文件保持原位置；切换方案、停用普通包、分类归档和重复清理都跳过固定文件。固定包仍可分类、收藏，收藏只改标记。
- **管理固定**：`AI 与设置 → 固定基础包 → 管理固定基础包`，也可用资源库“固定基础包”状态筛选。详情有“固定基础包 / 解除固定”，选中后的工具栏支持批量操作。自动保留的依赖显示上游包；解除上游固定后，若仍有其他固定包需要它，会继续保留。设置和文件转移均有恢复记录。
- **基础收藏**：默认动态方案保留原 ID 和副本偏好。点击“预览启用 → 确认执行”后，新收藏自动启用并带上可用依赖；取消收藏后移回普通分类，不再需要的依赖停用，固定包继续常驻。切换其他方案、恢复全部或停用普通包后停止自动跟随。手动新增到收藏目录的 VAR 在更新索引后纳入；不会自动启动 VaM。
- **首次整理 / 以后重整**：`启动方案 → 停用普通包并整理` 将非固定包移入停用库并按主分类整理，收藏在其内部单独分类。基础包原位保留。已关联的图片、说明及内部子目录始终跟随主资源文件夹；无法明确归属的散落附件保留目录结构，停用普通包与恢复全部时随库转移。
- **悬浮操作栏**：勾选资源后，顶部选择栏滚出原位时悬浮，使用半透明磨砂背景；滚回上方自动归位，与底部分页栏一致。

固定列表保存在 `data/base-packages.json`，默认收藏方案标识保存在 `data/launch-settings.json`，整组目录关联保存在 `data/resource-folders.json`。分类来自索引，修改简介/主分类不会自动移动文件，需执行“按分类归档”。新增下载或导入完成后会按当前已应用方案同步启停；未应用方案时只启用固定基础包。操作需先退出 VaM；保留恢复日志，从新到旧撤销。

## 使用顺序

1. **更新索引**：递归扫描所有 VAR，读取元数据与包内文件目录。**深度扫描**还检查场景、预设等文件中的依赖引用。
2. **添加资源**：支持多选 `.var` 或选择整个文件夹，递归复制 VAR、常见图片与说明文档，保留原文件和文件夹层级。自动分析新包简介、分类与依赖；已应用按需方案时新包进入停用库。压缩合集需先解压。
3. **资源库**：搜索名称、作者、简介和路径；按类型/状态/收藏筛选；列表行首显示包内封面，可切换大图网格并记住展示方式，分类在列表和封面右上角以独立彩色标签展示，详情查看依赖与位置。支持选择本页或全部筛选结果。收藏与资源库均有“一键 AI 简介”，弹窗选择全部重新生成或仅补充未生成，不受搜索筛选影响。
4. **重复清理**：校验 SHA-256 后预览清理。同名不同内容全部保留，不同版本不合并。副本移入隔离区，不立即释放磁盘空间。
5. **依赖检查**：查询 VaM Hub；根据包内作者链接发现 GitHub Releases，并支持添加正规网站公开下载页、VAR 直链或 JSON 目录。匹配依赖的发布文件后下载并核对响应完整性、全包 ZIP CRC。作者、包内名称、服务器文件名、体积或发布 SHA-256 不一致均保留原 VAR，以黄色 **!** 展示差异；元数据无法读取也保存并标为读取异常。提示跟随移动和重启保留。无法获取的付费、私有、下架资源仍会列出。
6. **启动方案**：可保存固定主包，也可从全部收藏或指定文件夹创建动态方案。每次预览、启用时重新纳入来源中的包及递归依赖，其他包暂移至停用库；保存不立即切换。切换完成后点 **启动 VaM**，也可恢复全部启用。
7. **对话助手**：连续对话推荐资源、检查依赖、移动/归档、创建和启用方案、补包、恢复操作。文字推荐后展示可点开的封面卡片，可直接收藏。默认可以执行你要求的管理操作；勾选“只读推荐”可限制助手为查询。
8. **收藏夹**：普通包在收藏和普通主分类目录之间移动；固定包只更新收藏标记。基础收藏已启用时同步启用范围，否则保留原启用状态。支持批量操作和恢复。

例如：“推荐几个本地跳舞场景，检查依赖是否齐全”“把选中的包移到 收藏/精选，创建名为日常的启动方案”“启用日常方案并启动 VaM”“恢复刚才的移动”。助手通过固定包管理 API 执行，工具过程与结果可展开查看，支持停止和新对话；重启后继续原对话。

也可以说：“收藏你推荐的第一个包”“把全部收藏创建为一个动态启动方案，先不启用”“把 收藏/人物 整个文件夹做成启动方案”。文件夹来源包含子文件夹及停用库相同相对路径。当前安装已将 `AddonPackages/自定义包` 整夹改名为 `AddonPackages/收藏`，作为收藏目录，1.11 起收藏按主分类放入 `收藏/主分类/`。手动放入收藏目录的新 VAR 在下次扫描时自动收藏。

## 按需启用与目录改名

“基础收藏”等来源为“全部收藏”的方案自动同步新增/取消收藏，递归依赖随最新名单计算；界面显示 **自动更新**，无需反复保存。收藏清空时保留方案，下次新增后恢复可用。手动放入收藏目录的新包在更新索引后计入；预览启用也会先扫描。其他固定或文件夹方案按各自来源计算，不自动并入全部收藏。

直接点击收藏方案的 **预览启用** 使用动态名单。**复制为固定选择** 只复制当时的名单，另存的固定方案不再跟随收藏。预览后若收藏、方案或依赖解析变化，旧预览会停止执行，需重新预览；不会按过期名单移动资源。

保存方案只记录选择或动态来源。启用时递归计算依赖，将所需 VAR 保持/移回 `AddonPackages/`，其余非固定 VAR 移到游戏根目录的 `.未启用模组/`，保留相对路径、文件名与文件内容。同盘通过重命名移动，无需复制大包；游戏退出后切换，完成后再启动 VaM。退出游戏不自动恢复全库；可切换另一个方案或点击“恢复全部启用”。1.10 起，缺失依赖仅提示，仍可启用所有可用包；完全不可读取的包跳过。整个方案没有可用包、同名副本未选定或预览过期时仍会阻止执行。

### 同名副本的两种选择（1.9）

进入 **启动方案 → 预览启用**，在“同名副本”选择处理方式：

- **指定副本**：按路径、大小和可读取状态选择一份；其余放入停用库。相同内容自动选一份，只有一份可读取时自动选它。依赖按所选文件计算。
- **全部保留**：同名文件都启用，保留各自目录及原 VAR 名；依赖汇总各份可读取副本的声明。VaM 对同一作者、包名、版本的 UID 只注册一份，采用顺序不保证，也不会自动合并内容。此模式保留文件，不保证每份资源都能在游戏中使用。

修改后点击 **更新预览**。勾选“记住此启动方案的选择”会在更新预览时保存偏好，确认执行才移动文件。各方案独立记忆，临时选择另存；记忆以 SHA-256 识别内容，路径变化仍能匹配，所选内容消失后要求重新选择。即使依赖缺失或无需移动，也可以保存偏好。缺失依赖不会阻止启用；整个方案没有可读取包或仍有副本待选时不能执行。无需移动文件的方案也可确认执行，记录按需启用状态。

转移时若完整相对路径也重名，增加 `原目录/包名/副本-编号/` 子目录，不重命名 VAR、不覆盖文件；“恢复全部启用”也按此规则保留所有文件。操作记录保留实际路径，可恢复到操作前。副本选择不替代 VaM 内部资源或插件兼容性判断。

`POST /api/rename-favorite-folder` 接受 `{ "folder": "收藏" }`，整夹改名，包括图片、说明和空目录；同步索引、收藏设置及按文件夹保存的方案。操作记录可撤销，先恢复后续文件操作再撤销改名。

## 文件夹导入（1.10）

**资源库 / 收藏夹 → 添加资源 → 选择文件夹 → 导入并分析**。递归复制 `.var`、`.jpg`、`.jpeg`、`.png`、`.webp`、`.gif`、`.bmp`、`.txt`、`.md`、`.pdf`、`.json`；其他文件跳过。一次最多 10,000 个支持文件；单个 VAR 上限 20 GiB，附件 512 MiB。RAR / ZIP 合集先解压，VAR 本身保持压缩格式。

- 未应用方案或最近应用的是按需方案：新资源存入 `.未启用模组/包管家导入/`，不改变当前启用名单。恢复全部启用后，新资源进入 `AddonPackages/包管家导入/`。
- 单选/多选 VAR 按内容分类存放；文件夹导入保留 `所选文件夹名/原子目录/原文件名`。同名文件夹增加序号，目标文件仍冲突时增加副本子目录，不覆盖文件或改 VAR 名。
- 完全相同的包跳过；同名但内容不同的包保留为独立副本并显示 **!**。包内作者/名称不符也提示保留；无效 ZIP 或 CRC 损坏拒绝导入。已有手动或 AI 简介保留，新包可自动分析。
- 图片/说明不作为独立依赖索引，保留原子目录；识别为整组资源后，归档、收藏与主包启用都会携带附件。卡片封面仍优先使用 VAR 内的图片。
- 上传流式读取，显示进度；“停止上传”在当前文件复制结束后清理暂存，不加入资源库。进入导入校验任务后取消会保留并索引已经复制的部分，未处理暂存清理。导入只增量索引新增 VAR，不重新解析全库。

“预览启用”只计算包与转移清单；“确认执行”才移动 VAR；“启动 VaM”是单独动作。未打包的场景/脚本和其他游戏文件不属于按需停用范围。大图选择框的半透明白边由 5 px 缩为 2 px，资源库和收藏夹一致。

## 一键 AI 简介（1.12）

收藏和资源库页点击“一键 AI 简介”，先在弹窗选择模式，再点击“确认开始”：

- **全部生成 / 重新生成（默认）**：为本次范围内所有可读取的包生成简介和主分类，成功后替换已有 AI 或手动内容。
- **仅补充未生成**：按持久化完成记录跳过已完成包；只补充未生成或内容已变化的包。判断不依赖旧简介文字是否存在。

收藏页范围是本轮开始时的全部收藏，资源库页是全库，均包含停用包，不受搜索、类别、当前页或勾选影响。勾选包的“生成简介”也提供同一弹窗，只处理所选范围。读取异常的包跳过，修复并更新索引后可再生成。

Codex 每次请求最多 10 个包，DeepSeek / 兼容 API 最多 5 个包，完整结果分批保存后继续。点击“暂停”会完成并保存当前批次，然后释放后台任务；可继续浏览和管理资源。刷新网页保留进度；生成期间需保持至少一个包管家页面打开。关闭最后一个页面会停止生成并退出后台，重启工具后暂停等待“继续生成”，不会自行消耗额度。网络/额度错误会停在当前批次，已保存结果保留。可“结束本轮”后选择另一个范围，已完成简介仍保留。队列期间仍可浏览、搜索；需要移动资源等操作时先暂停。

遇到回复截断、空内容、JSON 格式或结果不完整时，自动拆小批次；单包最多重试一次，每组最多增加 6 次恢复调用。完整子批次即时保存，继续时跳过本轮已完成项；HTTP / 额度错误、模型拒绝和用户取消不自动重试。不会补括号或保存残缺简介。DeepSeek 官方 `deepseek-flash` / `deepseek-v4-pro` 简介保留 `max_tokens=8192` 输出余量；思考强度统一请求 medium；DeepSeek 官方把 medium 映射到 high，不代表比默认 high 更低。最近一次解析异常的结束原因、长度和用量保存在 `data/ai-response-diagnostic.json`，不记录密钥、回复正文、推理正文或图片。

新加入的包在下一轮纳入；继续收藏队列时会跳过已取消收藏的包。队列存于 `data/summary-queue.json`，完成标记存于 `data/catalog.sqlite3` 的 `summary_state` 表，按包 UID（含版本）记录，不写入 VAR。简介与标记一起提交；本轮成功保存的包在续跑时跳过，新一轮“全部生成”则重新处理。

首次启用标记时，保留已有简介但把现有包初始化为未生成；不会在以后重启时反复清零。新包自动建记录，目录移动、收藏及启停不清除标记；扫描或导入发现文件大小 / 修改时间变化时重新标为未生成，旧文字仍保留。成功生成或明确手动保存非空简介才标为完成，仅改分类 / 收藏不算。备份和迁移应用时保留 `data/catalog.sqlite3`；删掉索引也会丢失完成记录。单包仍可在详情“AI 重新分析”。

## 对话预设（1.13）

对话输入框上方常用栏最多显示 5 个预设，右侧 **›** 展开全部预设。内置人物、服装、发型、舞蹈、启动方案、查重、依赖和收藏等 10 个入口。点击标题只填入输入框，发送前仍可修改；预设栏在对话过程中也保持可用。

在面板内勾选“常用”决定展示哪些，选满后先取消一个再替换。支持新增、编辑和删除；每项需填写标题与提示词。先填标题，可点击 **AI 生成提示词**，使用已保存的服务和对话模型，根据标题及现有内容生成草稿。结果放入编辑框，可修改后保存；失败或停止保留原文字，返回列表或关闭面板会取消未完成生成。

自定义内容与常用选择保存在 `data/chat-presets.json`，跨重启和浏览器保留；首次修改前使用内置默认值。删除全部后保持空列表，不会下次启动又补回默认项。生成预设是独立请求，不向当前对话发送消息或调用资源管理工具。

## AI 接入

- **Codex**：内置官方 CLI 0.163.0，沿用当前 Windows 用户的官方登录。ChatGPT 登录使用订阅权限；API Key 登录则属于 API 用量。简介/导入分析默认 `gpt-6-luna`，对话默认 `gpt-6.1-sol`，两者独立设置；下拉列表自动读取 CLI 返回的所有模型（含隐藏/专用项），可手动刷新；显示识图、推理等能力标签。填写程序路径可覆盖内置 CLI；未改动全局安装。
- **DeepSeek / 兼容 API**：配置基础 URL 和 Key 后自动读取 `/models`；和 Codex 一样分别选择 **对话模型**、**简介生成模型**，刷新保留各自选择。对话与预设提示词使用前者，批量简介 / 导入分析使用后者；简介识图能力也按后者判断。旧配置首次读取时，两个选项都沿用原 API 模型，不改写密钥。密钥通过 Windows DPAPI 加密，绑定当前 Windows 用户，不返回给页面。简介和预设生成需支持 Chat Completions JSON 模式；对话管理还需支持 `tools` / `tool_calls`。
- **API 服务切换**：DeepSeek 使用官方地址与下拉模型列表；“其他 OpenAI 兼容 API”提供可编辑地址和可输入匹配的模型框。两种服务分别保存地址、对话／简介模型、密钥和上下文容量。切换只更新表单，不立即改变运行服务；当前页面内保留各自草稿，点击“保存设置”保存当前服务。旧版单套连接按原服务／实际地址保留，读取不改写配置；未保留的另一服务密钥需重新填写，不会跨服务复用当前密钥。
- 其他兼容 API 的模型选择框可直接输入完整模型 ID，也可输入部分 ID 或显示名称匹配列表（不区分大小写），点击或用方向键＋Enter 选择；右侧箭头展示完整列表。对话与简介模型独立保存，刷新列表不覆盖手填值；接口不提供 `/models` 时也可手填。基础地址例如 `https://api.siliconflow.cn/v1`，模型 ID 按供应商返回值原样填写，保留组织前缀、斜杠和大小写；保存地址与密钥后读取列表。硅基流动使用 `sub_type=chat` 筛选对话模型；其他接口按已声明的元数据排除非语言模型，未声明能力时不猜测，实际调用权限以服务端为准。
- 能力标签区分识图、推理、工具调用、JSON 输出及上下文，并标明来源。读取输入模态、`capabilities`、`supported_parameters` 等声明；缺失字段可由内置的硅基流动官方资料补充（仅匹配已核对的接口与完整型号，详情附出处和核对日期）。在其他兼容 API 中展开模型下方“能力来源与手动设置”，可选自动／支持／不支持，再点击“保存设置”。手动设置按接口地址与完整模型名保存，优先于接口声明，接口声明优先于资料补充；选择自动即移除对应覆盖。识图设置实际控制图片发送资格，仍受“参考包内封面”等原有开关约束；其他能力设置用于标注，不自动修改调用格式或添加思考参数。缺失信息保持“未确认”，能力声明不等于账户调用权限或当前开启状态。
- 生成简介发送作者说明、均衡抽取的代表文件名及最多三个场景/预设的类型线索；“参考包内封面”开启且所选模型支持识图时，每包附一张预览，过滤透明度/纹理贴图，较大的图片批次自动拆分。对话发送你的消息及相关查询、路径和操作结果，使用已保存的简介推荐资源；不上传 VAR。批量生成使用可暂停队列，每次请求最多 10 个包；是否覆盖由确认弹窗的模式决定。简介要求“类型＋具体内容/用途”，建议 3–5 句话、尽量简短，无硬性字数或句数限制；人物优先补充性别呈现、资料年龄段或外观年龄观感、最明显的外貌特征及造型风格，无法确定的内容直接省略。成人题材使用有依据、克制的目录式说明，不泛化为普通展示。
- AI 结果可手动修正。导入时 AI 不可用会保留本地分类，资源仍会加入。


### 模型思考强度

界面不再提供强度选择。对话、预设提示词生成、批量 / 单包简介和导入分析统一请求 **medium（中）**，不受旧配置中的强度值影响；对话与简介仍可分别选择模型。

Codex 按 `model/list` 确认支持 medium，再通过 CLI 参数和每轮对话设置；不支持的模型使用其默认值。DeepSeek 官方 Flash / V4 Pro 接受 `reasoning_effort="medium"`，但服务端实际映射到 **high**，与默认 high 相同，不应据此预期降低用量。其他兼容 API 仅在模型元数据声明 medium 时附加该参数，否则使用服务默认。

旧强度字段读取时忽略，下次保存设置时清理；不会为此重写 Key 或重置生成队列。升级后关闭全部包管家网页，等约 8 秒再打开原 EXE 即可。

官方说明：[OpenAI Docs：Codex 配置](https://learn.chatgpt.com/docs/config-file/config-reference)、[DeepSeek 强度映射](https://api-docs.deepseek.com/guides/thinking_mode/)。

## 速度与界面

列表 / 大图和排序自动保存在 `data/library-preferences.json`，收藏与资源库共用；重启 EXE、更换端口或浏览器后仍保留。只记住展示方式和排序，状态筛选沿用原行为。

资源库、收藏和依赖清单使用半透明磨砂分页胶囊：多页时悬浮在内容区底部，滚到页面底部自动归位；只有一页时保持内联。四个图标依次为首页、上一页、下一页、末页；中间页码可编辑，按 Enter 跳转，超出范围自动定位到有效页。启动方案的已选列表也使用这组按钮，但不悬浮。

收藏页的分类数量按收藏范围、关键词和状态统计；点击某一分类后，其他分类的数量仍显示其可用结果，方便切换。顶部数量、启用数、副本数和占用空间统计完整筛选结果，包含所有页。收藏范围内可继续筛选已启用、已停用、未生成简介、异常或感叹号提示；返回左侧“资源库”恢复全库范围。

取消收藏使末页变空时，自动回到有效页。搜索、收藏或分类更新会同步更新计数，保留正在输入的搜索框；“选择全部结果”沿用当前筛选范围，过期查询不会追加旧范围的选择。已有选择跨页、跨筛选保留，批量操作前可查看数量或点击“清空”。

封面从原 VAR 按需读取，场景/外观预览优先，排除皮肤贴图。最多四个并发请求；服务端缓存最多 256 项/48 MiB，浏览器缩小到最长边 640 像素并缓存最多约 120 张。资源库和收藏夹的列表、大图统一每页 42 个包，无预览的包显示类型图标。对话使用本地 Marked + DOMPurify 渲染 Markdown，支持表格、列表和代码块，不依赖在线 CDN。

补包页面按当前索引重算清单，已拥有的包退出待下载；结果区分别显示安装成功、失败、解决依赖和新引入依赖。新依赖可能抵消减少量；查询来源与安装数量并不是同一个指标。

同盘转移使用重命名；操作意图分批持久化，移动后直接更新索引。增量扫描复用文件状态，搜索/依赖结果缓存；大选择列表分页，搜索保留输入焦点，进度更新不重建整个页面。


## 界面配色

在 **AI 与设置 → 界面外观** 选择森林绿、海洋蓝、鸢尾紫、玫瑰粉、琥珀橙或石墨灰，并选择浅色、深色或跟随系统。右上角月亮 / 太阳按钮可快速切换明暗模式。即时生效，自动写入 `data/appearance.json`，重启 EXE、更换浏览器或端口仍保持选择；多开的页面同步设置。封面原色不变，切换外观不会中断任务。

左上角图标和浏览器标签页图标随主题同步换色；浅色、深色及跟随系统均适用。

补包结果中的“已保存”只表示原文件保留，不代表在 VaM 中运行通过。元数据无法读取的文件仍计入缺失，不重复下载同一份已标记文件；网络截断、HTML 登录页和 ZIP CRC 损坏仍报错。已有文件不会被覆盖。可在状态筛选选择“有感叹号提示”，点击 **!** 查看具体差异。

文件操作先生成计划，执行前再次核对文件状态。页面操作显示确认预览；对话助手会根据你明确的执行要求调用计划和执行 API，无需每一步再次点击。只想看方案时明确说“先预览，不执行”，或开启只读推荐。中途关闭或出错，进入 **操作记录** 恢复；建议按从新到旧的顺序恢复。恢复遇到文件变化或路径占用会停止，避免覆盖。

点击星标直接执行收藏归档，不再额外弹出确认；仍检查游戏已关闭和路径冲突，并保存恢复日志。推荐卡片仅打开资源详情，不直接播放场景。升级工具集合时会保留可见对话记录，将最近上下文带入新的 Codex 线程；后续启动恢复此线程，避免旧线程缺少新增工具。

重复校验中的“预览清理”只将副本移入隔离区。需要释放空间时，在“重复清理 → 隔离区”查看清单、预览并确认永久清理；删除后相关批次无法再由操作记录整批恢复。**移走或删除整个工具目录前，先恢复全部启用，并恢复需要保留的隔离副本。** 停用库默认在游戏根目录的 `.未启用模组/`，自定义后使用设置中的名称；旧版本可能仍用 `data/disabled/`，以启动方案页显示的位置为准。 Git 只能回退源码，不能恢复被永久删除的包。

按需启用以 VAR 声明和深度扫描的文字引用为依据。运行时动态拼接的依赖、未打包本地场景及会话插件的包不能保证自动发现，请一并加入方案。单个文本文件超过 32 MiB 或包内文本总量超过 96 MiB 时会跳过超限项，并在详情标注。包扫描不是每个包的 CRC 全检，读取异常会单独显示。

管理页面只绑定 `127.0.0.1`，每次启动生成会话令牌，校验 Host / Origin。最后一个管理页面关闭后，通常约 5–8 秒自动退出后台并释放内存；这段宽限用于刷新重连。多页面、最小化和切到其他标签页不触发退出。页面崩溃断开连接也会退出；启动后 90 秒没有任何页面连接则自动退出。后台退出前取消任务、保存 AI 队列暂停状态并关闭自身启动的 AI 子进程；文件操作等待当前步骤及恢复记录写完，耗时取决于正在执行的操作。下次双击 EXE 重新启动，简介需点击继续。设置页“退出包管家”也支持停止运行中的任务。

## 本地工具 API

`GET /api/agent/tools` 返回 12 个包管理工具的 JSON Schema；`POST /api/agent/tool` 接受 `{"name":"search_packages","arguments":{"q":"Timeline"}}`。新增 `show_packages`、`list_folders`、`set_favorites`；`manage_profiles` 支持 `folder` 或 `favorites: true`，启用使用 `plan_files(kind=activate,profile_id=...)`，不受返回列表的预览条数限制。请求须携带当前 `data/server.json` 对应的 `X-Session-Token`，不要把真实令牌写进脚本仓库。接口实现在 `src/vampm/server.py` 与 `src/vampm/agent_tools.py`。

Windows 可用 `runtime\python.exe -m unittest discover -s tests -v`。重建运行环境执行 `python tools/prepare_runtime.py`，固定官方来源及 SHA-256；`python tools/prepare_codex.py` 安装官方 npm 发行版并校验固定 SHA-512。然后用 PowerShell 运行 `tools/build.ps1` 编译 EXE。浏览器测试仅在临时测试库中操作，不使用实际游戏资源。

`tests/benchmark.py` 仅使用临时生成的测试资源测性能。`tests/windows_*.js` 是保留的历史手动检查脚本，部分断言对应旧界面，运行前需审阅并显式设置 `VAMPM_MANUAL_WINDOWS_TEST=1`；这些脚本会读取本地安装、部分会改界面偏好和保存截图，不属于当前自动回归。`tests/windows_lifecycle.py` 需显式传入 `--allow-local-library`。显式运行 `runtime\python.exe tests/live_agent_workflow.py` 可用当前 Codex 账号重测真实三轮对话及临时库移动/恢复，会使用账号额度。普通单元/浏览器测试不调用真实 AI。

显式执行 `runtime\python.exe tests/live_collections.py` 可在临时花园测试库验证旧对话升级、新工具、卡片、收藏移动与动态方案；使用当前账号额度。

### 1.7 详情与识图

点击资源列表行或大图卡片可打开详情；勾选和收藏独立操作，键盘聚焦卡片可按 Enter / 空格。详情封面按原比例完整显示，切换包时回到顶部。模型列表缓存 24 小时，可随时刷新；新 Key 和接口地址保存后自动重新发现。API Key 使用 Windows DPAPI，仅在调用配置的 API 时解密为认证头，模型缓存不包含 Key。已有简介不会自动重写，在详情中使用“AI 重新分析”。


### 1.8 紧凑卡片与对话布局

资源库与收藏夹的大图封面统一为 1:1 方形，宽度铺满卡片，高度随卡片宽度变化。常见方形图完整显示，不产生容器留白；少量非方形图按原比例居中铺满并裁边。信息区保持紧凑，简介默认两行省略；长简介旁的向下箭头可原位展开，再点收起，点击卡片仍查看完整详情。短简介隐藏展开按钮，列表保持原有单行展示。推荐卡片采用相同的两行简介和独立展开控件，类型标签放到封面上。

对话助手占用可用窗口高度，标题、状态与操作合并为一条工具栏；输入区固定在底部，历史消息独立滚动。常用预设为紧凑单行，窄窗口可横向滚动，右侧全部预设入口保持可见。大屏不再限制为 760px，高度较小和手机尺寸窗口仍保留输入区。

分类仅表达内容：人物、服饰、头发、场景、插件等，不再提供“依赖”分类。旧“依赖”标签根据已有文件类型索引显示为内容分类，未知内容显示“其他”；无需重新扫描或调用 AI，原简介和收藏保留。依赖检查、递归补包和按需启用照常处理包之间的引用关系。
